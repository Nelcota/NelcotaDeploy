# Engineering conventions

Rules for new and changed code. They describe how the codebase already works where it works well, plus the target rules from [target state](../architecture/target-state.md). Where a rule is not yet enforced, the [roadmap](../refactoring/roadmap.md) stage that enforces it is named.

## Language and repository

- English for everything except `web/i18n/pt_br.go` ([AGENTS.md](../../AGENTS.md)), enforced by `internal/policy`.
- Generated code (`internal/gen`, `internal/store/dbgen`, `*_templ.go`, `web/static/dist`) is never edited by hand; change the source and run `make generate`.
- Credentials, databases, backups, and release artifacts never enter Git, including test binaries (`*.test`).

## Packages

- A package is named for what it provides (`supervise`, `fsx`, `mail`), never `utils`, `helpers`, `common`, or `misc`.
- Business rules and authorization live in `internal/service`. Delivery packages (`internal/httpapi`, `web`, `internal/transport`) parse input, call one service method per use case, and render the result.
- Interfaces are declared by the consumer, next to the code that uses them (`internal/service/ports.go`), and stay small.
- Only `cmd/*` wires concrete adapters into services. Services receive dependencies through a constructor, never through field assignment after construction.
- Allowed import edges are listed in [target state](../architecture/target-state.md#dependency-rules-enforced-by-e7) and enforced by a test (S6).

## Errors

- Service methods return `*service.Error` with a `Kind` for anything the caller should act on; the message is written for the person using the interface and contains no internal details or third-party error text.
- Unexpected errors are wrapped with `%w`, logged once where they are handled, and returned untyped; delivery layers turn them into a generic internal error.
- One function maps `Kind` to HTTP status, shared by the JSON API and the interface (S7).
- Never match on error message text; add a `Kind` or a sentinel instead.
- `context.Canceled` from a departed client is not an error to log.

## Validation

- Validate at the service boundary, once, for every entry point (interface, API, agent events). Delivery layers may pre-validate for usability but never instead of the service.
- Agents also validate commands they execute (paths, ports, sizes), even though commands are signed.
- Bounded inputs: every collection, string, and body has a documented maximum.

## Concurrency, context, and loops

- Every goroutine has an owner that waits for it; packages that start goroutines run goleak in tests.
- Every call that leaves the process (HTTP, SMTP, SSH, Docker, BuildKit, Caddy, GitHub) has a deadline.
- Long-running loops run under `supervise.Supervise`: errors are logged and retried with backoff; only startup and listener failures stop the process ([ADR-0004](../architecture/decisions/0004-supervised-background-loops.md)).
- Work started by a command belongs to the component that executes it, not to the connection that delivered it ([ADR-0003](../architecture/decisions/0003-agent-jobs-outlive-control-sessions.md)).

## Data

- All SQL lives in `internal/store/queries` and is generated by sqlc (S8). Multi-step writes use `Core.mutate`, with the audit row in the same transaction.
- Updates of contended rows check the expected state: `revision` for apps, current `status` for deployments.
- Every migration has a working down section and is covered by the migration test (S0).
- Side effects that must not be lost are written to an outbox table in the same transaction ([ADR-0005](../architecture/decisions/0005-durable-notification-outbox.md)); the in-process hub is only for live views.

## Logging

- `log/slog` with one configured handler per binary (S11). Messages are lowercase phrases; context goes in attributes with standard keys: `loop`, `server`, `app`, `deployment`, `request_id`, `err`.
- Never log secrets, tokens, environment values, or full request bodies; use the redactor for build output.

## Configuration

- Each binary reads configuration once into a validated struct; flags and environment variables map to the same fields (S6). Invalid configuration stops startup with a message naming the field.
- Defaults are safe: loopback for diagnostics, HTTPS origins outside development mode.

## Tests

- Tests sit next to the code (`_test.go`); integration tests use the `integration` build tag and fail without real infrastructure.
- Known defects are written as skipped tests that name the finding, never as assertions of wrong behavior.
- Prefer real SQLite and local HTTP, SMTP, and TLS servers over mocks; use fakes for ports.
- Benchmarks use `b.Loop()`; performance claims cite benchstat output.

## Naming

- Errors are `err` (not `e`) in new code; receivers are short and consistent per type.
- Status and stage names come from typed constants (S7), not string literals.
- Functions above cognitive complexity 30 are split before new behavior is added to them (S5 threshold).

## Documentation

- Structural decisions get an ADR ([decisions](../architecture/decisions/README.md)).
- Behavior visible to operators is documented in [operations](../operations.md) in the same change.
- Claims about verification say where they were verified: locally, in CI, or on a VPS.
